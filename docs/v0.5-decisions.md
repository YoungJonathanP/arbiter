# v0.5 decisions — headless core

*Decision record, 2026-07-09. Choices made while implementing the v0.4.4 contract as code (library + CLI). Grammar patched to v0.4.5 (§9); PROTOCOL.md is unchanged at 0.4.4 — nothing here alters agent-facing behavior, only writer-side determinism and interpretations the spec left open.*

## Stack (confirming the launch plan's standing recommendation)

TypeScript throughout, strict; one package with `src/core/` (parser, serializer, normalizer, schemas-as-data, validator, facts, index, queries, dashboard, arbitrate, triage) and `src/cli/`; `better-sqlite3` for the derived index — a disposable cache, never truth (gate 5). No YAML dependency: the grammar restricts frontmatter to a flat mapping (one nested level in schemas), and a hand-rolled parser keeps untouched entries byte-stable, which gates 2–4 need. Tests are `node:test` via `tsx`; gates 1–7 run against `fixtures/arbiter-data/` with the staged conflict's arbitration pinned byte-exact in `test/expected/`.

## Spec patches (grammar v0.4.5, all in §9)

1. **Empty `.staged/` after arbitration** — the open nit from the v0.4.4 review. Decided: `arbiter arbitrate` removes the directory it empties; leaving it is equally conforming (an empty staging directory means nothing is pending). One SHOULD sentence added.
2. **Resolution-line placement** (deferred as cosmetic in the spec-readability test, but gate 7 makes it byte-visible): resolution lines form one contiguous block at the end of `## Summary`, preceded by exactly one blank line when the summary doesn't already end in a resolution line.
3. **Synthesized `blocked-by:` link**: a blocked mark-op applied by arbitration lifts the **first** distinct md-link of its proposal's body. Independent arbiters must pick the same link or confluence breaks on multi-link bodies.

**Not patched — asserted:** the evidence-link separator in resolution lines was already comma-space in the §9 `evidence` production; the test suite pins it (`arbitration.test.ts`).

## Interpretations (code-level, revisit with cause)

- **Triage archive timing**: "terminal work items" are archived only once past their 7-day dashboard age-off (archiving them sooner would contradict the age-off window, since archived items never appear); records are archived when older than a quarter (90 days). Accomplishments are archived but never deleted.
- **Status recompute in arbitration**: `dropped` is a judgment call, never contradicted by structure; `done` requires all steps `[x]`; `blocked` requires a `[!]` step; a multi-way conflict among explicit statuses that structure cannot adjudicate (e.g. `todo` vs `in-flight`) escalates to `needs-review` rather than guessing.
- **Full rebuild reconciles the previous dashboard when present** (hand-added entries, and dates for raw items — dated evidence beats checkout-falsified mtimes, per PROTOCOL.md#normalization). Only rebuilding a *deleted* dashboard falls back to mtimes.
- **Triage touches bump `updated`** (needs-review and archive stamps are real writes), so incremental regeneration observes the transition. Staged proposal files remain non-touches per §7.
