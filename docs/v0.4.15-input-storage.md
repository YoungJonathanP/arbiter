# 0.4.15: durable linked-input review and local human task actions

Decision: repository candidate, 2026-09-11. Implements part of the agreed
[app direction](user-app-direction.md); installed KB adoption remains explicit.
Protocol/grammar advance to 0.4.15. Base remains 0.4.14 and concrete item schemas
retain their versions because the new storage is a separate file role.

The pure review model previously lost all receipts at process exit and could not
establish that incorporation reached canonical task bytes. The candidate now stores
link incarnations, relationship edges, revision receipts and write intent in one
private, append-only Markdown audit ledger per task. [Grammar §18](grammar.md#18-linked-input-audit-storage-0415)
defines the exact layout. Prior event bytes and the final pointer remain stable;
new events insert before the pointer. Event hashes establish sequence, and CAS plus
staging checks protect cooperating writes. This is not cryptographic actor identity
or an atomic transaction across the ledger and task/source files.

Task/source effects first retain exact before/after intent, then commit and reread
the content, then append completion. A prepared effect is not a receipt. Interrupted
input actions block further actions until explicit reconciliation. Reconciliation
never writes the target: unchanged before bytes cancel; exact after bytes complete
non-review effects; unrelated bytes require content reconciliation. Interrupted
incorporation always cancels receipt intent, retaining landed prose and actionable
input for a fresh review. Filesystem transaction recovery remains separate.

The default local task app offers quick notes with an optional event date, pending
input bodies with explicit presented/deferred/dismissed actions, Done and Undo.
The existing loopback/origin/token guard supplies the local-operator capability;
request fields cannot choose actors or grant private access. Done with unfinished
parsed steps requires an explicit checklist choice. Pending proposals remain an
arbitration gate. Undo requires exact task bytes from the latest completed status
action, then restores prior status/checklist/prose with a new touch time. The
protocol narrowly exempts these explicit human controls from terminal-transition
staging; agent writes retain their prior safeguards.

The library additionally supports attributed incorporation with a reviewed body,
link/unlink, durable relationship connect/disconnect and a trusted audience-policy
interface. Relationships and links have independent shared/private visibility;
private edges between shared endpoints stay hidden. Relationships never set task
owner, grant access or create accounts. Incorporation preserves existing body,
anchors and the final pointer, appending attributed text and updating only the
touch metadata. It checks source/link audience coverage and verifies content before
receipts. These checks do not detect arbitrary sensitive prose supplied by a caller.

Checkpoint preview includes every actionable shared input's exact bytes, source
revision and disposition in the whole-packet budget. New revisions mark the packet
review-required. Presented/deferred inputs remain actionable. Capture/export
recheck the preview and never silently acknowledge input. No audit body, private
edge, private source count, reviewer or review reason is exported. Last input review
is derived independently of task `updated`; the local view displays only timestamps
from readable associations. Core storage retains the complete private audit.

The HTTP tests exercise real note capture/review, Done/Undo, stale requests, origin
rejection and forged-grant rejection on synthetic initialized KBs. Storage tests
exercise interruption, concurrent edits, exact history, relinking, independent edge
privacy and restricted exports. The existing pure-model tests remain. These are
local synthetic acceptance tests, not installed live-app or fresh-agent results.

Remaining adoption work is concrete: personal principal authentication and trusted
policy administration; person/entity schemas and connected-person cards; appointment
entry; a preview UI for attributed incorporation; complete active-work overview
reconciliation against the user's directive; and selected evaluation-target
migration with verified original refs/anchors, capture/export and rollback.
The historical seven-file proposal must not be installed. A fresh full-contract
candidate is retained privately with hashes, but is not declared compatible with
all agreed app outcomes. The current 0.4.7 live KB and its copies remain untouched.

T09 stays partial until compatible adoption/migration and authorized isolated
fresh-session evidence exist. Fresh-session execution and live rollout remain
separate gates; this decision supplies neither authorization nor measured results.
