# v0.4.10: Recover structured entries around malformed lines

One annotated link previously made an entire Artifacts or Detail docs section
opaque. The same failure affected checklists. Readers now retain valid entries,
malformed lines and internal blanks in source order. Writers normalize recognized
entries while preserving malformed line bytes, including trailing spaces.

The AST keeps existing `steps`/`entries` arrays for facts and op consumers, with
`rawRows` recording entry indices, opaque lines and blanks. Entries and
continuations carry optional 1-based `rawLine` positions; continuations retain
intervening blanks. Positions refer to the parsed input snapshot, including
frontmatter. In-place entry mutation and appends are supported by `orderedRows`;
future removals/reordering must update row indices. Semantic equality includes
ordered opaque material but excludes coordinates. Reparse serialized output before
using positions to edit a changed file.

A malformed checklist line ends continuation attachment. Continuations following
it remain opaque until another valid step; this avoids guessing their owner.
Blank lines alone preserve attachment. Canonical section separators and CRLF-to-LF
normalization retain the existing contract; this is not whole-file byte identity
for noncanonical input. Unknown sections and legacy malformed AST nodes remain
opaque. Duplicate headings remain separate; arbitration still rejects ambiguous
append destinations.

Malformed entries produce warnings with line and expected production. Parsed
missing paths/anchors produce distinct broken-target errors. The renderer displays
valid navigation and escaped unresolved source with a repair diagnostic. Default
visible source projections remove private lines and carry a source-line map
to retain original diagnostic coordinates without changing frontmatter parsing;
filtered raw previews can have fewer lines. No unfiltered bytes feed renderer diagnostics.
Literal privacy filtering still cannot classify arbitrary paraphrased secrets.
HTTP(S) targets are accepted without network existence checks. Raw human files
retain their existing warning-only validation behavior.

Annotations are accepted within labels, titles and checklist text before an
optional anchor. Trailing annotations after link targets, document paths or step
anchors remain malformed. This strict boundary makes a production's meaning
unambiguous. Both grammar and bootstrap protocol/base schema advance to 0.4.10;
concrete field schemas remain 0.4. Existing 0.4.6, 0.4.8 and 0.4.9 KBs remain
accepted without rewriting frozen or installed corpora.

Arbitration parses append input and rejects any opaque residue before deciding
an op. Valid appends and marks can operate in mixed sections; preserved malformed
text never satisfies an op. Entry comparison ignores source metadata, preventing
new line positions from defeating deduplication or postconditions. Recoverable
commit and privacy guarantees from T02/T03 continue to apply.

Evidence is in `test/parser-recovery.test.ts`, the updated mixed-section assertion
in `test/safe-writes.test.ts`, and the unchanged canonical conformance gates.
