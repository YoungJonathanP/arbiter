## Acceptance evidence

The synthetic assignment round-trips and validates with owner, authority,
constraints, row/ticket IDs, selected revisions and a concrete next action. A second
checkpoint replaces it while the first remains byte-identical under its hash path.
The receiving assessment uses current visible files without history and remains
ready; the new next action and still-applicable constraints are directly present.

Tests change a dependency without touching timestamps and observe review-required;
explicit contradictions, unknown owners/workspace revisions and unknown predicates
are also visible. An unmet predicate waits without altering in-flight status.
Missing authority content and malformed metadata are unprepared. Repo inputs require
caller-provided observations, and evidence anchors are checked against parsed rows.

CAS contention cannot replace another checkpoint; owning staged intent blocks a
capture; history changes and legacy-detail repurposing are refused. An injected
failure after journal preparation leaves old bytes/history intact; recovery installs
the exact second version. Changed historical bytes fail whole-KB validation.

Plan inputs normalizes ahead of Checklist without losing ticket IDs/anchors or
produced-artifact links. Unicode-aware budget tests include the complete emitted
string, and enforce explicit larger maxima/reasons. Size warnings identify Summary,
row anchor/source line and checkpoint, without changing the content. Fresh KBs have
distinct UUIDs; private task ownership excludes its checkpoint from projection.

## Limits and successor

Capture/preview/export commands and editable UI are T06. Pure budget assessment
accepts a full string; T06 must assemble the exact packet, record overrides, apply
visibility/readiness gates and bind copy/export to preview revisions. Machine checks
cannot prove prose authority, predicate evidence or live external state. The receiver
must check workspace/branch/authority and selected external/repo revisions.

Generic writes do not validate the full input manifest under lock or atomically
change task metadata and checkpoint. T06 owns that capture coordination; the
existing commit path remains single-file and cooperating-local-writers only.
Extra immutable snapshots from failed captures are retained, not treated as cache.
Source walking still reads the corpus before projection filtering; history is
excluded from returned/default context, not a new lazy filesystem indexing API.

Installed KBs are not upgraded from a design alone. `$ARBITER_DATA` still selects
the frozen repository corpus; `../arbiter-data` remains absent. Live dogfood capture,
regen and validation there were unavailable; this record captures the session in
repository documentation. Neither frozen corpus, Finance Hub, USB KB, shell
profile nor installed KB was modified.
