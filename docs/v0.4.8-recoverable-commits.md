# v0.4.8: Verified arbitration and recoverable commits

Decision, 2026-09-06; T02. The Detail docs regression demonstrated that a
successful parse and an “applied” resolution line did not establish an effect.
CLI and triage also performed unlocked writes followed by proposal deletion.

The pure resolver now parses append entries through the target grammar, handles
all five eligible headings including missing sections, and verifies serialized
fields, marks and entries before assigning success. Malformed/unsupported
proposals stay staged. Immutable identity/capture fields are protected. Ambiguous
marks and duplicate headings are not guessed. A terminal item retains its terminal
status when a reopening proposal is escalated; otherwise a second pass could
reopen the item after the first replaced `done` with `needs-review`.

`src/core/commit.ts` is the persistence boundary. The existing better-sqlite3
dependency provides a corpus-wide `BEGIN IMMEDIATE` lock, automatically released
on process death. This deliberately serializes unrelated items too, avoiding
stale-PID lock reclamation races. The SQLite file is a lock implementation, not
an authoritative index or journal. All CLI item writers, normalization, dashboard
regeneration, arbitration, triage and proposal scaffolding cooperate through it.

Fsynced JSON journals retain complete before/after bytes, original proposal intent,
immutable proposal IDs/digests and per-op dispositions. The target is replaced by
same-directory temporary-file rename, followed by byte and semantic verification.
A complete receipt precedes digest-checked proposal deletion. Recovery finalizes
an observed replacement or replays against an unchanged base. Divergence preserves
observed external bytes and records a conflict; it never overwrites that version.
A fresh-base reconciliation or new proposal can continue while the old conflict
remains durable evidence. Identical proposals cannot reapply overruled operations;
ID reuse with different content remains staged. Back up `.arbiter/transactions/`
with the KB; it is canonical history, not disposable cache.

These guarantees require cooperating writers on a local filesystem. External
editors can still race between the final base check and rename, or after final
verification. Detected changes preserve snapshots, but there is no honest atomic
CAS claim against arbitrary external editors, network filesystems or hardware
that does not honor fsync. A multi-item command can commit a prefix before a later
conflict; journals show exactly what landed. Recovery inspection is read-only with
`recover --dry-run`; `recover` mutates. Validation reports outstanding journal
states without performing recovery. Disk-full/corrupt-journal errors stop work;
intent that reached a journal remains available for manual inspection. History
compaction and automated three-way conflict merging are outside T02.

New human-readable verdicts go under `## Arbitration history`, leaving current
Summary context and historical prose in place. Machine receipts live outside the
item in `.arbiter/transactions/<UUID>.json` (format version 1). T05 must keep its
future current-checkpoint replacement lifecycle separate from this append-retained
history; no checkpoint role or schema is introduced by T02. T03 must distinguish
these commit records from event timestamps and derived cache inputs.

Grammar and bootstrap protocol/base advance to 0.4.8. Canonical bootstrap assets
now live in `assets/contract/`, independently of both frozen corpora. Concrete type
schemas remain 0.4. New init uses those assets, including the previously documented
checklist progressive-disclosure guidance. Existing protocol/base 0.4.6 corpora
remain accepted without implicit rewriting; new receipts use the extended writer
contract, and the history heading remains opaque to old parsers. Installations
should adopt the new protocol guidance explicitly; downgrade writers cannot claim
the new guarantee. Neither frozen corpus nor shell profile changes.

Tests cover parsed Detail docs effects, all append variants, malformed proposals
beside valid ones, same-base CLI races, SIGKILL before/after replacement and before
cleanup, replay of overruled intent, changed-ID collisions, external edits,
recovery conflicts, triage stale snapshots and normalization journals. The old
spec-derived arbitration oracle changes only receipt placement, never fixture
bytes or verdict semantics. Completion evidence is recorded in
[the T02 completion record](handoffs/completed/t02.md).
