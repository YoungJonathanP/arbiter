# v0.4.9 — Current projections and independent review

Decision, 2026-09-07, T03. Grammar, bootstrap protocol and base schema are 0.4.9;
concrete schemas stay 0.4. Existing 0.4.6/0.4.8 KB identities remain accepted,
with no automatic source migration. Frozen conformance corpora remain unchanged.
This supersedes the timestamp invalidation and status absorption interpretations
in v0.5-decisions.md; the recoverable commit contract remains in force.

Current bytes determine current facts. The incremental API delegates to full
projection because its caller already reads every file. `updated` retains event/
touch semantics, and pure arbitration uses only input timestamps. No new wall-clock
revision field or persistent cache was needed. Quoted timestamps are unquoted for
sorting and maximum-date comparisons. SQLite is rebuilt from visible current facts;
deleting it preserves the active set. Transaction journals are not a cache.

`readProjection` reads a corpus once, derives schemas from those bytes, filters
visibility, and returns visible files/facts plus a SHA-256 digest. CLI regen/query
and renderer use it. The renderer recomputes cards on each request; human, agent
and raw dashboard routes use that same output. `generated` alone cannot establish
freshness. The source digest excludes generated dashboard bytes; age-off depends
on the supplied day, and legacy raw entries may retain an earlier dashboard date
as historical evidence. Pure callers receive a fact digest when no source digest
is supplied; those digest domains are not interchangeable. Reads are not an atomic
multi-file transaction: concurrent external edits require another refresh.

The selected audience is the default agent audience, also applied to the local
renderer. Private items and their owned files, and private standalone documents,
are excluded before deriving edges, children, staged rollups, counts and overflow.
Queries carry only relationships to visible existing items. Preview source lines
containing known private titles/identifiers are omitted; original source bytes
are untouched. This deliberately conservative literal filter may omit a public
line with a coincidentally matching title. It cannot recognize arbitrary copied
or paraphrased secrets; authors remain responsible for classifying source prose.
There is no include-private switch or public export bypass in this task.

Unresolved carried entries and opaque dashboard strays lack visibility evidence;
projections omit them. CLI regen retains the old bytes in its canonical commit
journal, allowing explicit recovery/classification of human additions. It does
not invent public item stubs. The read-only renderer does not change stored bytes.
Journal snapshots can contain private history and must never enter raw/export routes.

Review is optional universal `review: needed | legacy-unknown`. Triage stamps
needed and updates touch time, preserving status and checklist/blockers. Unresolved
arbitration stamps review while retaining valid execution results, including terminal
status protection. Review is sticky; explicit review removes it. Legacy
`status: needs-review` stays accepted and projects as legacy-unknown without inventing
a prior status. A reviewer selects an evidence-backed status and resolves review.
T05 must introduce checkpoint readiness separately; this task does not implement
checkpoint files. Legacy schemas accept new metadata as preserved optional fields;
new bootstrap schemas explicitly validate its enum.

Children are promoted as soon as their parent becomes terminal, even during the
parent's seven-day card window. This avoids a time-dependent hidden-child route.
Private, archived, missing and cross-directory parents likewise cannot hide children.
Invalid cycles retain roots for navigation while validation continues to reject
cycles and unsupported nesting depth.

Regression evidence lives in `test/projections.test.ts` and `test/serve.test.ts`:
same-minute/older/quoted edits, delayed pure arbitration, privacy across routes and
queries, independent blocked review, legacy unknown state, parent reachability,
input digest changes and physical SQLite deletion/rebuild. Existing canonical
fixture tests still pin the old bytes; the dashboard reproduction assertion only
allows the added input-provenance field.
