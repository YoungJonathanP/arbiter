# v0.4.7 decisions- checklist steps are summaries (progressive disclosure)

*Decision record, 2026-08-03. Protocol 0.4.6 → 0.4.7; grammar stays at v0.4.6
(the rule constrains prose length and placement, not the machine-read subset-
the checklist production, continuation lines, anchors, and `see:` grammar are
all untouched). Directive: long-running work items were accreting
paragraph-length checklist rows (the empiricist multi-repo task reached 57KB,
dominated by row prose), which floods a continuation session's context with
history it did not ask for. Tier 2 already had `see:` lines and tier 3 already
existed for exactly this material; the protocol just never said the row itself
must stay small.*

## The rule

- A checklist step carries **what it is, its current state, and the next
  action**- a few lines at most- plus any load-bearing operational rules and
  identifiers (PR links, standing constraints, anchors).
- **Detailed history**- shipping narratives, attempt-by-attempt run logs,
  review rounds, defect write-ups, verification evidence- belongs in a
  tier-3 detail doc linked from the step's `see:` line and listed under
  `## Detail docs`.
- When a step outgrows its summary, **relocate the detail verbatim** into its
  doc (append under a dated heading) rather than deleting it: the row keeps
  the conclusion and the next action; the doc keeps the story. Nothing is
  lost- it moves down a tier.

## Settled design points

1. **Why tier 2 and not a length lint.** The failure mode is contextual, not
   syntactic: a session asked to "continue where we left off" reads the tier-2
   file whole, so every byte of row prose is a context tax on continuation.
   The rule therefore lives in PROTOCOL.md#tier-2 next to the checklist
   grammar, phrased as a placement rule (summaries up, history down) rather
   than a character budget.
2. **Verbatim relocation, dated heading.** Tier 3 is read-mostly and
   append-under-dated-heading by existing rule, so relocation composes with
   it: the moved prose lands as a dated section and stays byte-preserved.
   This keeps the no-information-loss guarantee checkable.
3. **Standing rules stay in the row.** Operational constraints a continuing
   session must not miss (e.g. "never rebase this stack") are part of the
   summary, not the history- the rule explicitly carves them out.
4. **Enforcement is prose-first.** The validator does not yet flag oversized
   steps; a warning (e.g. on rows past some line count) is a candidate for the
   trial-feedback backlog, not part of this bump. Machines parse rows the
   same either way.

## Gate impact

None. No production changed; conformance gates 1-7 are unaffected. The CLI's
protocol-version fallback and help string were updated 0.4.6 → 0.4.7 for
consistency (`src/cli/main.ts`); `protocolRaw` reads the live PROTOCOL.md
frontmatter regardless, so regeneration stamps the new version without a code
dependency.
