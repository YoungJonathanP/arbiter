# v0.4.12 decisions — reviewed capture and handoff bytes

T06, 2026-09-08. Bootstrap protocol/base advance 0.4.11 → 0.4.12 to replace the
historical tooling-future statement with the shipped lifecycle. Grammar links this
implementation. Checkpoint file shape and concrete schemas (0.4) are unchanged;
0.4.6/8/9/10/11 remain accepted. No installed KB is upgraded implicitly.

## Shared interface

`src/core/handoff.ts` owns `draftCheckpoint`, `previewHandoff`, `captureCheckpoint`
and `exportHandoff`. CLI and localhost HTTP use this same implementation. A request
names a task object ref, optional draft checkpoint Markdown, optional owner,
format (`markdown` or `json`), offline mode, explicitly expanded KB input paths,
caller-observed repository/external revisions, optional extraction and a size
override. Unknown observations remain unknown. URLs never trigger network I/O.

A preview contains exact task and checkpoint before/after bytes, optional
extraction history, complete packet, byte count, assessment, actionable diagnostics
and a deterministic token over all derived state and the request. The input basis
covers current corpus bytes and visibility/staging, excluding dashboard and prior
checkpoints. This deliberately invalidates some previews after unrelated edits;
it avoids using timestamps to miss changes. It does not expose private paths,
contents or counts. The token detects change; it is not an authentication credential.

On capture/export, reconstruct and compare the preview, then use only reconstructed
fields. Tampered derived fields cannot become writes. Export of a draft is refused:
capture first and select the current version. The task view checks that the new
current preview still equals the reviewed draft packet before enabling copy/export.
The preview envelope is a review artifact; export its `packet`, not the envelope.
CLI stdout exports exact packet bytes without an extra log line or newline. Format
is fixed at preview time; browser download and clipboard receive that same string.

## Capture, preservation and failure

`withCommitSession` holds the existing SQLite writer lock across recovery,
revalidation and the separate journaled writes. Extraction history is retained
first, then task metadata, then the current checkpoint. Task pointer/owner edits
are included before computing its new input hash. Only an input matching the
observed pre-edit task may be refreshed automatically; stale selected decisions,
dependencies or task inputs cannot be captured without a new observation.

Task body bytes survive metadata edits unchanged; untouched checkpoint nested
records keep their raw frontmatter lines. Explicit Summary/anchored-row extraction
uses the parsed editable surface, keeps its anchor and compatibility link, retains
an exact full original task snapshot in a new linked tier-3 note, and copies the
extracted context into the current checkpoint. This preserves rules and identifiers
without requiring history reads. It never manufactures a semantic summary or
silently decides which rule is obsolete. The author supplies the replacement.

There is no multi-file atomicity claim. A crash between task and checkpoint can
leave a new pointer or owner with an old/missing checkpoint; no checkpoint bytes
are discarded. Refresh from disk, inspect/recover journals if needed, explicitly
re-observe changed inputs, then draft/capture again. The first-capture interruption
exercise verifies this recovery path. Cooperating writers serialize; external
editors and network filesystems remain outside the lock guarantee. Extra retained
snapshots remain evidence, not disposable cache.

## Packet context and privacy

Normal packets include the exact current checkpoint, complete task and entire
installed `PROTOCOL.md#checkpoints` section. Input manifest entries name revisions,
purposes and included/omitted status; observations also remain in checkpoint inputs.
Optional input content is expanded only by explicit KB path. `expand: ["PROTOCOL.md"]`
includes the full installed protocol. History and transaction journals cannot be
selected. Normal projections now skip checkpoint history during traversal, as well
as excluding it from returned context.

Offline mode bundles the complete installed protocol, base/task schemas and all
selected KB input contents. This avoids guessing which installed rules are optional.
It usually exceeds 10 KiB and therefore requires an explicit larger maximum and
reason in the preview. Repository/external sources remain identities and observed
revisions: no arbitrary local filesystem reads or network fetches. Offline packets
support planning until the receiver resolves KB/repository identities and checks
workspace, inputs, authority and live gates. Unready packets remain explicitly
labelled planning snapshots; an override cannot make them ready or grant authority.

The complete emitted UTF-8 string is measured, including its own stable byte count,
manifest, protocol and override. Warn above 6 KiB; refuse export above 10 KiB unless
the recorded larger maximum/reason permits it. Never truncate. Protocol inclusion
makes even compact normal packets approach the ceiling; the warning is deliberate.

Known private content is excluded by the shared policy. Any selected text that
would require redaction is refused rather than exporting incomplete rules. Common
credential assignments, token forms, private keys and credential-bearing URLs also
fail closed. Arbitrary secrets and paraphrased private facts cannot be recognized
reliably; authors must review content. No secret scanner can prove prose is safe.

## Local task view

The task view exposes current-version selection, draft Markdown, owner, next action,
dependency predicates, options, previewed changes and exact packet bytes. Save is
explicit. Copy and file export revalidate before emitting bytes and refuse stale
previews. Inputs invalidate prior previews; controls wait for pending requests.

The new POST API requires a per-server random token, loopback peer and Host, matching
local port, same Origin when present and JSON content type. It bounds request size
at 1 MiB. Cross-origin/DNS-rebinding attempts fail. Canonical frozen-data guards also
apply to HTTP capture. General file editing is not exposed by this endpoint.

## CLI workflow

Always select the intended KB explicitly when operating in this repository.

1. `arbiter checkpoint tasks/<id> --data <live-kb> > draft.md` emits a current-derived
   draft (or an explicitly unprepared scaffold). Edit its observed facts and rules.
2. Write a JSON request with `ref`, `checkpoint` (the draft string), optional `owner`
   and export options. `arbiter checkpoint tasks/<id> --file request.json --data
   <live-kb> > preview.json`. Inspect `packet`, `taskBefore`, `taskAfter`, `checkpoint`,
   `assessment`, `diagnostics` and any extraction history.
3. `arbiter checkpoint tasks/<id> --capture preview.json --data <live-kb>` saves the
   exact reconstructed draft under CAS. A stale preview exits 3; invalid usage exits 2.
4. `arbiter handoff tasks/<id> --format markdown --data <live-kb> > current.json`
   selects the current checkpoint. Supply `--file options.json` for offline mode,
   expansion, observations or a size override. Inspect the complete packet.
5. `arbiter handoff tasks/<id> --export current.json --data <live-kb> > handoff.md`
   emits exactly `current.json`'s packet. JSON format uses the same flow. Redirection
   is explicit shell file export; the command itself never overwrites arbitrary paths.

Example options (the maximum/reason must be deliberate, not copied by default):

```json
{
  "ref": "tasks/example-2026q3",
  "format": "json",
  "offline": true,
  "override": { "maxBytes": 65536, "reason": "Carry full installed rules for offline planning" }
}
```

A request's `observations` maps `repo:<relative-path>` or HTTP(S) identity to an
observed revision. Re-observe externally before producing a new preview; saved
observations are snapshots, not live verification. Capture never changes status,
clears review or infers that a supplied authority statement grants new permission.
