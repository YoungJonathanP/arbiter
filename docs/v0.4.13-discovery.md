# v0.4.13: Bounded discovery and navigation

Task and goal cards previously grew without a limit, and goal pages omitted task
children. Search and directory lists now use the same selection function for human
pages and agent JSON. The bootstrap protocol and base schema advance to 0.4.13
because the former contract required every top-level work item on its card.
Concrete schemas remain 0.4. Legacy 0.4.6/8/9/10/11/12 remain readable; installed
contracts are never upgraded by search or rendering.

`arbiter search "copper decision" --tiers 3 --archive include --json --data <kb>`
finds archived detail by content without knowing its filename. Terms are literal,
case-insensitive AND matches across title, path and visible source text. Title
matches rank first, then nonterminal before terminal, then recency descending
(updated for work, date for records), then source path ascending. This is a scan of
current visible files, not a persistent full-text index.

Defaults: tiers `2,3`, archive `exclude`, zero-based page `0`, page size `10`.
Select any of tiers `1,2,3`; archives accept `exclude`, `include`, `only`. Optional
`--dir`, `--status`, `--parent`, `--page` and `--page-size` narrow results. Maximum
page size is 50; titles are at most 160 characters and previews 240. JSON includes
the normalized options, exact total, page, page size, next page or null, and rows.
Follow next pages to reach the complete selected set. A new page reads current
files, so changes between requests can change membership; there is no snapshot
cursor or atomic filesystem read.

The renderer exposes `/search` and `/dir/<dir>` with equivalent query parameters
(`q` for text); `format=json` emits the shared result. Directory lists select tier
2 and include nested and aged-off terminal items. Archives are explicitly opted
into, including when a detail's owning item is archived. Tier 1 search derives the
current bounded dashboard instead of searching stale stored bytes. Schema and
protocol files, proposals, transaction journals and checkpoint history are outside
search tiers. Visibility filtering happens before matching and counts; existing
known-token redaction cannot recognize paraphrased private facts.

All dashboard groups and sidenav groups show at most five items and provide a
directory route with totals. Card membership, terminal age-off, same-directory
nesting and staged rollups are preserved. Goal-to-task children appear in bounded
direct-child lists; `search --tiers 2 --parent goals/<id>` returns the same rows.
Parent affiliation is visible regardless of directory. Checklist `blocked-by`
links and checkpoint predicates have a separate paged dependency section and agent
JSON. Child/dependency pages share the page controls on an item. Item source and
its existing sections remain inspectable in full; relation bodies are not loaded
recursively. Legacy index `query` APIs retain their existing output contracts;
use `search` for bounded discovery.

Task results and pages show only the current checkpoint's assessed readiness,
short next action, up to three diagnostic previews, diagnostic total and source
link. Required observations remain unknown when discovery has not observed the
repository or external system. No history is read or embedded. The handoff panel
lists selected inputs with each input's purpose as its reason. Only explicit
`expand` paths selected in those inputs add source bodies; changes require a fresh
preview. Exact capture/copy/export reconstruction, privacy and size checks remain
unchanged.

Completed rows are muted. Existing Markdown `~~text~~` explicitly represents
superseded prose and renders as `<del>` independently of completion. No new work
status or durable supersession relation is invented here; T08 owns durable record
types and their provenance/supersession model.

T08 integration: discovery consumes `readProjection` facts and corpus file kinds.
It adds no canonical type table. Existing `ITEM_DIRS`, `DIR_TO_TYPE`, `TYPE_TO_DIR`,
dashboard card definitions, CLI directory checks and web labels still constrain
custom schemas; T08 must settle those together. Reporting is not implemented by
this change.
