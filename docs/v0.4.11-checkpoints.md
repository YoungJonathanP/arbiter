# v0.4.11 decisions — bounded task checkpoints

Decision, 2026-09-07; T05. Grammar, bootstrap protocol and base schema advance
0.4.10 → 0.4.11. Concrete schema versions remain 0.4 with additive optional task
fields and Plan inputs. Installed KBs are not automatically amended.

## Storage and authority

A task's optional `checkpoint` field names `tasks/<id>/checkpoint.md`, a stable
path whose bytes are the current version. This separate file role is explicitly
replaceable; ordinary tier-3 documents remain append-only. Old bytes are retained
at `tasks/<id>/checkpoints/<sha256-hex>.md` before replacement. History files keep
exactly the old current-file contents, including their own `previous` digest.
No Git checkout or opaque cache is needed to retrieve a historical version.

The shared single-file commit boundary checks CAS and the owning task's staging,
archives old bytes under the same local writer lock, then journals and atomically
replaces the current file. History creation is immutable and idempotent. Failure
before current replacement can leave an extra valid history file; that is harmless
and must not be garbage-collected as cache. Failure after preparation uses normal
journal recovery. This does not promise atomic task-plus-checkpoint capture or
protection against uncooperative editors/network filesystems. T06 must recheck
selected input revisions and preview bytes inside its capture boundary.

`previous` proves a replacement relationship, not completion or precedence of
contradictory decisions. History is excluded from default projections/raw routes;
explicit filesystem history inspection remains possible. Normal checkpoint reads
do not traverse previous versions; whole-KB validation checks history integrity.

## Identity and readiness

The installed protocol owns a portable `kb-id: urn:uuid:<uuid>`; init generates
one. A copied KB preserves its identity; an intentionally independent fork gets a
new one as an explicit migration. The task ref is immutable within that identity.
A checkpoint names a repository URL/logical URN and records branch/revision
observations; the receiving session resolves those identities to local paths.
Absolute paths and old permission statements cannot confer authority.

The task owns accountable `owner` and optional `phase` grouping; the checkpoint
copies owner as a checked observation. Missing/unassigned owners, explicit
conflicts, unavailable or changed selected revisions, unknown gate observations,
pending proposals and task review flags prevent an effective ready assessment.
Execution `status`, sticky `review`, and checkpoint `readiness` remain separate.
No timestamps resolve decisions. Predicate content and evidence are authored
judgments; machines validate their shape and declared states, not prose truth.

Inputs and predicates use the existing restricted-YAML nested mapping syntax
formerly reserved for schemas. Each stable record ID maps to a flat flow mapping.
The lossless document AST carries these bytes; `assessCheckpoint` exposes typed
inputs/predicates and a conservative effective readiness. KB paths are compared
against supplied source bytes. Repository/external observations are caller-supplied;
missing observations remain review-required. Validation makes no network requests.

## Context and compatibility

Plan inputs is an optional structured link section before Checklist in tasks and
goals. Outputs remain in Artifacts; existing external IDs, row anchors and `see:`
links stay accessible. Detail is split into documents; independent deliverables
become tasks. Goals coordinate broader outcomes, without inheriting child status
or treating phase order as a blocker.

Initial targets are 4 KiB overview, 1 KiB Summary, 400 Unicode code points per full
serialized checklist row, and 6 KiB complete handoff; ordinary export ceiling is
10 KiB. All emitted metadata, protocol excerpts, constraints and inlined sources
count. `contextBudget` measures supplied complete bytes and requires an explicit
larger byte budget and nonempty reason above the ceiling. T06 owns export gating,
recording the override inside the exact preview and reporting omitted material.
Size never justifies truncation. Validator surface warnings apply to 0.4.11 KBs;
legacy corpora retain their former warning behavior.

0.4.6/0.4.8/0.4.9/0.4.10 remain accepted without writes. Adoption requires an
explicit installed-protocol/schema upgrade, stable KB identity, and intentional
creation of task/checkpoint metadata. Old manual packets stay ordinary documents;
import preserves bytes in history/detail and carries relevant rules into the new
checkpoint. A legacy document already using the reserved checkpoint path must be
relocated verbatim with compatibility links before opting in; generic replacement
refuses to overwrite it. No import tool or automatic live migration ships in T05.

T05 supplies the contract, file roles, parser/serializer reuse, assessment,
validation, versioned bootstrap and generic write lifecycle. Capture forms,
commands, request-level source verification, export/clipboard, and fresh-session
UI are T06. This distinction is intentional, not a claim of shipped export UX.
